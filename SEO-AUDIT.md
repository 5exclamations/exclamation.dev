# SEO и AI-visibility аудит — exclamationdev.com

Проведён 2026-08-14/15 против живого сайта и рабочей копии репозитория.
Все выводы ниже получены из `curl`, локальной сборки, Lighthouse 12.8.2 и
`scripts/schema-check.mjs`. Там, где проверить не удалось, это сказано прямо
и с причиной — догадок в этом файле нет.

Что уже починено в коде, помечено **[исправлено]** с номером коммита. Что
нельзя починить из репозитория — в §7 «Делает человек руками».

## 0. Главная гипотеза: «сайт не в индексе»

**Гипотеза подтверждена. Технической причины на стороне сайта нет.**

Проверка индексации — по точной цитате с главной и по домену:

| Запрос | Результат |
| --- | --- |
| `"exclamationdev.com"` (веб-поиск) | ни одного результата с домена |
| `"Bakıda sayt, CRM və mobil tətbiq"` (точная цитата H1) | ни одного результата с домена |
| `site:exclamationdev.com` (Bing) | ноль результатов |
| `"exclamationdev.com"` (Bing) | ноль результатов |

Дальше я искал, что именно блокирует. **Не блокирует ничего из перечисленного:**

```
$ curl -sI https://exclamationdev.com/
HTTP/2 200
```

- `robots.txt` — `Allow: /` для `*`, Googlebot нигде не запрещён (§1.1);
- заголовка `X-Robots-Tag` нет ни на одной странице;
- `<meta name="robots">` нет ни на одной из 42 индексируемых страниц
  (`noindex, follow` стоит только на трёх 404 — так и должно быть);
- canonical на всех 42 страницах указывает на себя же на прод-домене;
- все 42 URL из sitemap отдают `200`;
- контент отдаётся в HTML, без JS (§1.8);
- ответ на User-Agent Googlebot/Bingbot/ClaudeBot/GPTBot — тот же `200`
  и те же 102 968 байт, что и обычному браузеру. Проверено пятью UA:

```
code=200 size=102968 UA=Googlebot/2.1
code=200 size=102968 UA=Googlebot/2.1 (Chrome-совместимый)
code=200 size=102968 UA=bingbot/2.0
code=200 size=102968 UA=ClaudeBot/1.0
code=200 size=102968 UA=GPTBot/1.1
```

**Вывод: сайт краулябелен и индексируем; его просто ещё не обошли.** Домен
недавно переехал на Cloudflare, внешних ссылок на него нет, и в Search Console
он, судя по всему, не заявлен — а без хотя бы одного из этих трёх сигналов
новый домен может не попадать в индекс сколь угодно долго. Это **P0, но
чинится не в репозитории** — см. §7.1 и §7.2.

При этом найдено четыре реальных дефекта, каждый из которых по отдельности
уменьшает шансы на нормальную индексацию и на цитирование в ИИ. Они ниже.

## 1. Индексируемость (P0)

### 1.1 P0 — Cloudflare подменяет robots.txt и блокирует ИИ-краулеров [исправлено частично]

Самая серьёзная находка по ИИ-видимости. Файл, который отдаётся наружу, —
**не тот, что лежит в `public/robots.txt`**. Cloudflare включён в режиме
managed robots.txt и дописывает свой блок **перед** нашим:

```
$ curl https://exclamationdev.com/robots.txt
...
# BEGIN Cloudflare Managed content

User-agent: *
Content-Signal: search=yes,ai-train=no,use=reference
Allow: /

User-agent: Amazonbot
Disallow: /

User-agent: Applebot-Extended
Disallow: /

User-agent: Bytespider
Disallow: /

User-agent: CCBot
Disallow: /

User-agent: ClaudeBot
Disallow: /

User-agent: Google-Extended
Disallow: /

User-agent: GPTBot
Disallow: /

User-agent: meta-externalagent
Disallow: /

# END Cloudflare Managed Content
```

Три последствия, все проверенные:

1. **CCBot и Bytespider были запрещены полностью.** В нашем файле для них не
   было ни одной группы, так что перебивать инъекцию было нечем. Common Crawl
   (CCBot) — корпус, из которого читает большая часть предобучения моделей и
   почти весь сторонний SEO-инструментарий; отсутствовать в нём — это
   отсутствовать далеко не в одном индексе.
2. **Для GPTBot, ClaudeBot, Google-Extended, Applebot-Extended, Amazonbot,
   meta-externalagent** возникает по две группы с одинаковым User-agent —
   `Disallow: /` от Cloudflare и `Allow: /` от нас. Парсер по RFC 9309 §2.2.2
   сольёт группы и разрешит менее строгое правило, то есть наш `Allow`
   победит. Парсер, который берёт первую совпавшую группу, увидит `Disallow`
   и уйдёт. Поведение недетерминировано, и это плохо само по себе.
3. **`Content-Signal: ai-train=no`** — это не директива обхода, а прямое
   резервирование прав по ст. 4 Директивы ЕС 2019/790. Оно запрещает обучение
   на контенте сайта, и ничем из репозитория оно не перебивается.

Бонусом Lighthouse считает итоговый файл невалидным — и это строка Cloudflare,
не наша:

```
robots-txt: "robots.txt is not valid" — 1 error found
  line 30: Content-Signal: search=yes,ai-train=no,use=reference
  → Unknown directive
```

**Исправлено в коде** (`public/robots.txt`): добавлены явные группы `CCBot`,
`Bytespider` и `anthropic-ai`, и записано, что делает инъекция. Теперь явно
разрешены все, кого вы просили: GPTBot, OAI-SearchBot, ChatGPT-User, ClaudeBot,
Claude-User, Claude-SearchBot, anthropic-ai, PerplexityBot, Perplexity-User,
Google-Extended, Applebot-Extended, CCBot, Bytespider, Amazonbot,
meta-externalagent, Bingbot — 17 групп.

**Полностью чинится только в дашборде** — §7.3. До этого наши группы остаются
попыткой перебить инъекцию, а не гарантией.

### 1.2 P0 — www отдаёт 200, а не 301 [исправлено]

`_redirects` содержал правило для www, и оно **никогда не срабатывало**:

```
$ curl -sI https://www.exclamationdev.com/
HTTP/2 200            ← полная копия сайта, не редирект
```

Причина: Cloudflare Pages сопоставляет источники в `_redirects` **только по
пути**. Источник с именем хоста (`https://www.exclamationdev.com/*`) не
совпадает ни с одним запросом. Правило выглядело рабочим и молча не делало
ничего.

Смягчало ситуацию то, что canonical на www указывает на голый домен — но
canonical это подсказка, а 301 это не подсказка.

**Исправлено:** 301 перенесён в `functions/_middleware.ts`, который видит
заголовок Host. Из `public/_redirects` правило убрано, на его место записано,
почему его там не может быть.

### 1.3 P0 — превью-домен `exclamation.pages.dev` открыт и индексируем [исправлено]

```
$ curl -sI https://exclamation.pages.dev/
HTTP/2 200            ← весь сайт, тот же контент
```

Заголовка `X-Robots-Tag` не было. `robots.txt` там отдаётся наш же, с
`Sitemap: https://exclamationdev.com/sitemap.xml`, то есть с прод-домена —
блокировать превью через robots.txt на статике невозможно в принципе, файл
один на все хосты. Canonical указывал на прод, что опять же подсказка.

**Исправлено:** тот же `functions/_middleware.ts` ставит
`X-Robots-Tag: noindex, nofollow` на любой хост, оканчивающийся на
`.pages.dev`. Именно заголовок, а не редирект: на этот алиас ссылается лог
деплоя Cloudflare, он должен продолжать работать для нас и не попадать в
индекс.

Проверка на `wrangler pages dev`:

```
Host: www.exclamationdev.com  → HTTP/1.1 301, Location: /is/fleks/ (путь сохранён)
Host: exclamation.pages.dev   → HTTP/1.1 200, X-Robots-Tag: noindex, nofollow
Host: exclamationdev.com      → HTTP/1.1 200, без X-Robots-Tag
```

### 1.4 P1 — `_headers` терял все заголовки безопасности [исправлено]

Не SEO, но найдено по дороге и это реальная поломка в проде.

```
$ curl -sI https://exclamationdev.com/
HTTP/2 200
cache-control: public, max-age=0, must-revalidate
x-content-type-options: nosniff
referrer-policy: strict-origin-when-cross-origin
                      ← ни CSP, ни HSTS, ни Permissions-Policy,
                        ни COOP, ни X-Frame-Options
```

При этом `/fonts/*` и `/og/*` свои правила получали, то есть `_headers`
применялся. Причина: `astro.config.mjs` генерировал секцию `/*` **дважды** —
заголовки безопасности сверху, `Cache-Control` отдельной секцией `/*` снизу.
Cloudflare Pages для повторённого пути оставляет **последнюю** секцию и
отбрасывает предыдущую. Выживал `Cache-Control`, всё остальное исчезало.

**Исправлено:** одна секция `/*`, `Cache-Control` внутри неё. Проверено на
`wrangler pages dev` — CSP и Cache-Control теперь приходят вместе.

### 1.5 P1 — sitemap: x-default вёл на редирект [исправлено]

21 из 42 URL в sitemap имели hreflang `x-default`, указывающий на адрес без
слэша, при том что `<loc>` и HTML-разметка той же страницы указывали со
слэшем:

```
<loc>https://exclamationdev.com/faq/</loc>
<xhtml:link rel="alternate" hreflang="x-default" href="https://exclamationdev.com/faq"/>

$ curl -o /dev/null -w "%{http_code} -> %{redirect_url}" https://exclamationdev.com/faq
308 -> https://exclamationdev.com/faq/
```

hreflang, ведущий на редирект, Google не переходит, а отбрасывает всю
аннотацию для этой страницы. HTML был прав, ошибался только генератор
sitemap: `x-default` строился из «сырого» пути вместо `localePath`.

**Исправлено** в `src/pages/sitemap.xml.ts`. После сборки: 0 из 42 x-default
без слэша, и все 42 hreflang-цели присутствуют в файле как `<loc>`.

## 4. Видимость в ИИ-поиске (P1)

### 4.1 robots.txt для ИИ — см. §1.1

Главная причина, по которой ИИ может не знать про сайт, найдена и описана

## 7. Делает человек руками

### 7.1 P0 — Заявить сайт в Search Console и Bing Webmaster Tools

Это первоочередное. Технических препятствий нет (§0), сайт просто никто не
обошёл.

1. `search.google.com/search-console` → добавить ресурс **домен**
   `exclamationdev.com` (не URL-префикс) → подтвердить TXT-записью в DNS.
   DNS уже в Cloudflare, запись добавляется там же.
2. Sitemaps → отправить `https://exclamationdev.com/sitemap.xml`.
3. Проверка URL → главная → «Запросить индексирование». Повторить для трёх
   локализованных главных и шести страниц услуг.
4. То же в `bing.com/webmasters` — туда же импортируется из Search Console в
   один клик, и это же кормит ChatGPT Search и Copilot.

После §1.2 и §1.3 отчёт «Страницы» покажет www и pages.dev как дубли — это
ожидаемо и рассосётся.

### 7.2 P0 — Получить хотя бы несколько внешних ссылок

Новый домен без единой входящей ссылки Google может не обходить очень долго,
даже с sitemap. Минимум:

  «разработка сайтов Баку»);

  реального URL;

- ссылка с GitHub-профиля `5exclamations`.

### 7.3 P0 — Выключить Cloudflare managed robots.txt

Cloudflare Dashboard → зона `exclamationdev.com` → **AI Crawl Control** (в
части аккаунтов — Security → Bots → Managed robots.txt) → **выключить**
управляемый robots.txt / блокировку ИИ-краулеров.

Это снимает разом: `Disallow` для восьми ИИ-ботов, конфликт дублирующихся
групп, `Content-Signal: ai-train=no` и ошибку валидации Lighthouse. Пока
включено — §1.1 закрыт только наполовину, кодом.

Проверить после: `curl https://exclamationdev.com/robots.txt` — блока
`BEGIN Cloudflare Managed content` быть не должно.

### 7.4 P1 — Две настройки Cloudflare, которые меняют выдачу HTML

1. **Email Address Obfuscation** → Scrape Shield → выключить. Сейчас почта в
   видимом тексте заменена на `[email protected]` (§1.7). JSON-LD не задет,
   но ИИ цитирует видимый текст.
2. **Web Analytics** → решить, нужен ли beacon. Если нет — выключить. Если
   да — сказать мне, я добавлю его origin в CSP; иначе после деплоя правки
   §1.4 он будет заблокирован политикой (§5.2).

### 7.5 P1 — Дать реальные цены «от», или подтвердить, что их не будет
