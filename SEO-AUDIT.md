### 1.1 P0 — Cloudflare подменял robots.txt и блокировал ИИ-краулеров [ЗАКРЫТО 2026-08-15]

### 1.2 P0 — www отдаёт 200, а не 301 [исправлено]

`_redirects` содержал правило для www, и оно **никогда не срабатывало**:

```
$ curl -sI https://www.exclamationdev.com/
HTTP/2 200            ← полная копия сайта, не редирект
```

Причина: Cloudflare Pages сопоставляет источники в `_redirects` **только по
пути**. Источник с именем хоста (`https://www.exclamationdev.com/*`) не
совпадает ни с одним запросом. Правило выглядело рабочим и молча не делало
ничего.

Смягчало ситуацию то, что canonical на www указывает на голый домен — но
canonical это подсказка, а 301 это не подсказка.

**Исправлено:** 301 перенесён в `functions/_middleware.ts`, который видит
заголовок Host. Из `public/_redirects` правило убрано, на его место записано,
почему его там не может быть.

### 1.3 P0 — превью-домен `exclamation.pages.dev` открыт и индексируем [исправлено]

```
$ curl -sI https://exclamation.pages.dev/
HTTP/2 200            ← весь сайт, тот же контент
```

Заголовка `X-Robots-Tag` не было. `robots.txt` там отдаётся наш же, с
`Sitemap: https://exclamationdev.com/sitemap.xml`, то есть с прод-домена —
блокировать превью через robots.txt на статике невозможно в принципе, файл
один на все хосты. Canonical указывал на прод, что опять же подсказка.

**Исправлено:** тот же `functions/_middleware.ts` ставит
`X-Robots-Tag: noindex, nofollow` на любой хост, оканчивающийся на

деплоя Cloudflare, он должен продолжать работать для нас и не попадать в
индекс.

### 1.4 P1 — `_headers` терял все заголовки безопасности [исправлено]

Не SEO, но найдено по дороге и это реальная поломка в проде.

```
$ curl -sI https://exclamationdev.com/
HTTP/2 200
cache-control: public, max-age=0, must-revalidate
x-content-type-options: nosniff
referrer-policy: strict-origin-when-cross-origin
                      ← ни CSP, ни HSTS, ни Permissions-Policy,
                        ни COOP, ни X-Frame-Options
```

При этом `/fonts/*` и `/og/*` свои правила получали, то есть `_headers`
применялся. Причина: `astro.config.mjs` генерировал секцию `/*` **дважды** —
заголовки безопасности сверху, `Cache-Control` отдельной секцией `/*` снизу.
Cloudflare Pages для повторённого пути оставляет **последнюю** секцию и
отбрасывает предыдущую. Выживал `Cache-Control`, всё остальное исчезало.

**Исправлено:** одна секция `/*`, `Cache-Control` внутри неё. Проверено на
`wrangler pages dev` — CSP и Cache-Control теперь приходят вместе.

### 1.5 P1 — sitemap: x-default вёл на редирект [исправлено]

21 из 42 URL в sitemap имели hreflang `x-default`, указывающий на адрес без
слэша, при том что `<loc>` и HTML-разметка той же страницы указывали со
слэшем:

```
<loc>https://exclamationdev.com/faq/</loc>
<xhtml:link rel="alternate" hreflang="x-default" href="https://exclamationdev.com/faq"/>

$ curl -o /dev/null -w "%{http_code} -> %{redirect_url}" https://exclamationdev.com/faq
308 -> https://exclamationdev.com/faq/
```

hreflang, ведущий на редирект, Google не переходит, а отбрасывает всю
аннотацию для этой страницы. HTML был прав, ошибался только генератор
sitemap: `x-default` строился из «сырого» пути вместо `localePath`.

**Исправлено** в `src/pages/sitemap.xml.ts`. После сборки: 0 из 42 x-default
без слэша, и все 42 hreflang-цели присутствуют в файле как `<loc>`.

### 2.5 Исправление: две прошлые правки лежали в скрытом тексте

В предыдущей версии я поставил «создание сайта» (ру) и «sayt hazırlanması» (аз)
в `introTitle` и назвал это «заголовком с высоким весом». **Это было неверно.**
`introTitle` рендерится так:

```html
<h2 id="svc-intro" class="visually-hidden">…</h2>
```

`.visually-hidden` в `src/styles/base.css` — `position:absolute; width:1px;
height:1px; clip-path:inset(50%)`. Это H2 для скринридера, пользователь его не
видит. Заметил это, когда скриншот изменённого блока не показал никаких
изменений.

Почему это плохое место, а не просто слабое: целевая фраза, помещённая в
невидимый пользователю текст, — это ровно то, что Google описывает как hidden
text в спам-политике. Сам заголовок легитимен, он существует для доступности и
описывает секцию, и моя формулировка была правдивой — но ставить туда фразу
**ради ранжирования** значит использовать элемент не по назначению.

Обе правки откачены, `introTitle` вернулись к исходным формулировкам. Фразы
перенесены в видимые элементы: русская — в H2 `pricing.title`, азербайджанская
— в лид страницы. Проверено скриптом, который вырезает
`.visually-hidden` перед подсчётом: все шесть фраз теперь в видимом тексте.

### 4.5 IndexNow — настроен [исправлено]

IndexNow — push-протокол: сайт сам сообщает, какие URL изменились, вместо того
чтобы ждать обхода. Один POST доходит до Bing, Yandex, Seznam и Naver.

Console.

Bing здесь и есть причина: ChatGPT Search отвечает из индекса Bing, поэтому
страница, которой Bing не видел, — это страница, которую ChatGPT не может
процитировать, сколько бы `OAI-SearchBot` ни разрешали в robots.txt.

Что сделано:

- ключ `e866a9130b5722ac10e88535db80e790`, файл в `public/`, отдаётся с корня
  домена. **Ключ публичный по устройству протокола** — он ничего не
  авторизует, кроме «этот хост может отправлять свои же URL», и эндпоинт
  обязан его прочитать. В секрет его прятать нельзя, это ломает проверку;
- `scripts/indexnow.mjs` + `npm run indexnow`. Читает `dist/sitemap.xml`,
  умеет `--dry-run` и `--url` для одной страницы, отказывается отправлять
